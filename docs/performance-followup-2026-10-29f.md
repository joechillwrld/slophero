# 0.4.141 rainbow color and frame follow-up

The user's v0.4.140 log and PresentMon raw files show the existing input-viewer suppression actually activated. Trimming the first and final second of each roughly 30-second capture gave 1,667 presented FPS with the viewer visible and 1,730 with it hidden. Median frame intervals were 0.588 and 0.564 ms; P99 intervals were 0.776 and 0.752 ms. Mean GPU busy fell from 0.241 to 0.227 ms. This one A/B pair favors hiding the 48-sprite viewer. It spans different chart sections and was not repeated; two rare 13–15 ms frames occurred in the hidden capture, so it does not establish a general worst-frame improvement. The existing setting remains optional and no new FPS gain is attributed to this build.

The 60 Hz rainbow cap executed about 1,781 palette passes in a 30-second log capture, consistent with a 59.4 Hz effective rate. The uploaded raw cap run has no otherwise matching uncapped run, so its presented-FPS impact is unknown. A log snapshot with `renderFrameInterval=1` was taken before active song play; later snapshots show 2. It must not be used to infer the capture's active interval, and the user reports using 2 throughout.

I also rechecked the earlier four-way sustain-candidate raw captures (one 30-second run per condition). `neither`, `skip`, `cache`, and `both` averaged about 1,664, 1,618, 1,592, and 1,632 app presents/s. The no-candidate run was fastest, but the chart workload and GPU busy were not fixed across the four sequential runs, and the `cache` run had an 85 ms startup stall. These are a reason to retest the optional native detours one at a time, not evidence to claim they always cost FPS. The Unity worker-limit experiment likewise has no consistent measured benefit in the older report. No saved opt-in was silently changed.

An exact `level2` scene asset inventory puts 15 enabled SpriteRenderers under `HUDCam/HUD/Score`, eight under `HUDCam/HUD/Combo`, eight under `HUDCam/HUD/Star`, and four under `HUDCam/HUD/Song Progress`, assuming serialized active ancestors. The live runtime count is lower than the serialized input-viewer population: only the 48 guitar sprites appear in the log. `HUDCam/Menu Canvas` deactivates most of its children already. The Score branch contains the game's live score digits; SlopHero's ordinary counter HUD does not replace that score. A new default-off **Compact score + combo HUD** experiment reads the two SpriteFont cached amounts at 20 Hz, adds both numbers to the existing counter Canvas, then hides only the 23 score/combo SpriteRenderers. The SpriteFont components and game scoring stay active. It requires the exact 15+8 scene structure and a successfully visible Canvas, restores the original renderer states on pause/exit/option-off, and leaves other HUD graphics alone. It can change the score position/font and lag the native digits by up to 50 ms. Whether it actually improves presented FPS is unknown until a matched Windows A/B; a retained Canvas may cost more than the removed sprites.

The compact HUD also checks each cached amount against the native font's displayed last digit before hiding its sprites. If the current game's field mapping or a modded font differs from the older source, it leaves the native score visible.

Version 0.4.141 changes three rainbow behaviors:

- A new song starts its moving hue cycle at a reproducible phase. Previously the phase used absolute game uptime, changing the initial colors after each restart even while slider numbers stayed fixed. The moving palette still advances normally and retains speed-change continuity.
- High saturation, contrast, and brightness now shape channels with a soft curve. The old luminance expansion and twofold RGB values clipped intermediate hues into plain primaries; at maximum saturation and roughly 165% brightness, this was particularly visible. Default settings preserve their prior channel values. This math cannot fully recolor an already colored source sprite: the supplied Moonlight normal note art has green/cyan pixels and only about 8% opaque white pixels, so its texture still limits the displayed spectrum.
- **Color variety across notes** defaults to zero, preserving lane-wide colors. Above zero, each pooled note gets a deterministic hue offset from its pool slot; it remains stable while visible and covers up to 60 palette positions rather than changing randomly every frame. The old pool-order bug produced many simultaneous colors but also made recycled notes flicker. This setting seeks the former without the latter. The expanded palette is computed only when variety is above zero. Flames retain their five-lane palette.
- When the hue cycle is stopped, the 30 Hz active-note scan reuses its palette until a color setting or flame source changes. This removes repeat HSV/curve calculations from a fixed palette, though the same 30 Hz scan still admits newly active pooled notes. Its FPS impact is unmeasured.

Native HUD scale restoration now reuses a key scratch list instead of allocating copies of its resize dictionary during each periodic restore pass. This is a small mod-side allocation removal, not a measured frame-rate improvement; the 0.4.140 log places the mod's ordinary Update near 0.001 ms on average.

The optional camera-timing capture now keys camera callbacks by their existing IL2CPP wrapper pointer instead of calling native `GetInstanceID` on every pre-cull/pre-render/post-render event. This only reduces the profiler's own work during a camera capture; it is not a normal-play FPS optimization. The pointer cache is cleared when each capture finishes.

The mod builds against the supplied assemblies with zero warnings/errors, and all 135 Core checks pass, covering the channel curve, default behavior, and all 60 variety positions. The release ZIP contains only `Mods/SlopHero.dll`; SHA-256: `f364c60ac9b4b7dd65d776b934f199b7fa0aba193c9060106879f95f8e7e638d`. Windows visual validation is still needed for the new palette, especially with the active note skin and ClonZones. Test normal vs. maximum variety while rainbow notes are on, then restart the same song and check the initial hue and smoothness. For performance, repeat a same-song input-viewer on/off PresentMon pair and a compact-score-HUD on/off pair with the rest of the settings fixed. Confirm the compact score/combo numbers match the game's native numbers before using its FPS result.

## Supplied 0.4.141 compact HUD capture pair

The newly supplied `compact off 1.csv` and `compact on 1.csv` are raw 29.95 s and 29.93 s PresentMon runs from the same process and swapchain. The two `* 2.csv` files are summary rows, not second raw runs. The off run has 55,251 presents (1,844.8/s), mean frame interval 0.542 ms, P99 0.693 ms, and mean CPU busy 0.515 ms. The on run has 54,900 presents (1,834.3/s), mean frame interval 0.545 ms, P99 0.706 ms, and mean CPU busy 0.518 ms. Frames at least 3 ms numbered 3 off and 5 on. This one pair does not show a compact-HUD performance gain; different chart moments and run order could account for the small difference. The captured `Latest.log` identifies SlopHero v0.4.141 but contains no `Compact score HUD replaced 23 native score/combo renderers` entry, so activation during these CSV intervals is not verified. Do not attribute their difference to the compact option or claim visual parity from this data.

The same log repeatedly reports that the optional personal-best popup suppression could not find its live target. The native regular-sustain cache reports 174 song-end summaries: 29 have nonzero skips and 145 have zero (153,166 skips total, maximum 54,156). The log alone does not show whether the nonzero skips improved presented frames. Those are separate unresolved performance leads, not measured gains. The supplied standalone `SlopHero.dll` is identified by the user as the latest build; its SHA-256 is `f313d7a5c2456d340fb3f63170d7b8ea32f4c44b4348eb024f201f9aed826b4a`. It is not a replacement for the game's loader and generated reference assemblies, which this environment still lacks.

The next-update working branch changes the compact HUD's value source from the older-build private `SpriteFont.lastAmount` mapping to the digits currently displayed by each native `SpriteFont`. The old mapping can reject a valid current build and leave the built-in score graphic visible. The replacement still requires both visible Canvas text and the expected HUD hierarchy before hiding native renderers. The working mod compiles against the supplied MelonLoader/generated game assemblies with zero warnings and 145 Core checks pass. A Windows visual check is still needed; it is not part of the 0.4.141 package.
